# Strategic Projection for SPaDE

## Introduction

The pace of advancement of LLM capabilities shortens time horizons for the development of SPaDE, and brings into the planning process considerations which were previously only relevant to the long term cosmic perspective.

This document provides my most optimistic projection of the future development path for SPaDE, to inform the transition to a largely autonomous and maximally parallel development process.

There are two sides to SPaDE which are interlinked but nevertheless can usefully be treated separately here.
These two sides should be progressed in parallel, and the development of each should be informed by the other.

- [The Articulation and Promulgation of Norms](#the-articulation-and-promulgation-of-norms)

## The Acceleration of AI by Focal Methods

SPaDE development begins with software developed in python kept in a git repository and managed with the benefit of the github ecosystem.
One of the early target capabilities for SPaDE is Deductive Engineering, beginning with software engineering.
Deductive Engineering in SPaDE is a formal process involving formal models held in a SPaDE repository.
The earliest software engineering tasks targetted will be SPaDE itself.
The specifications in the SPaDE git repository will be migrated into a SPaDE repository, and the development will increasingly be undertaken in SPaDE rather than github repositories.
