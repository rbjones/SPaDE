title: Contributing
---

Information for contributors to the [SPaDE](docs/tlad001.md#spade) project is at present somewhat disorganized and incomplete.

Initially the project is a collaboration between the repository owner (Roger Jones) and AI tools, primarily GitHub Copilot and Grok Build.

SPaDE is primarily philosophical and architectural in nature, and I therefore would expect that any humans who are persuaded by the rhetoric (or the technical content!) are likely to create their own projects buying in to the articulated SPaDE architecture, and hence contributing to a broader ecosystem.
Nevertheless, in the event that others wished to contribute to SPaDE itself, it is recommended that in the first instance they clone the GitHub SPaDE repo and submit contributions through pull requests.
In that case, they should acquaint themselves with the standards, procedures, methods and skills documented in the [docs/admin](./docs/admin/README.md) directory.

Working practice is indexed from that directory. The following are a useful start:

- [Roles, Responsibilities, Tasks](docs/admin/amms002.md)
- [Workflows](docs/admin/amms003.md)
- [Collaboration Guidelines](docs/admin/amms004.md)
- [Guidance for AI Contributions](docs/admin/amms005.md)
- [Working practice (Grok vs Copilot)](docs/admin/README.md#working-practice-pro-tem)
- [Branches, worktrees, and sessions](docs/admin/ampd004.md)
- [GitHub-scheduled Copilot; container tests](docs/admin/ampd001.md)
- [Independent review of Grok-authored PRs](docs/admin/ampd005.md)
- [Instructions for Copilot](./.github/copilot-instructions.md)

I encourage anyone interested in contributing to consider starting their own related project developing agents to supply specialist services in the network of agents which is envisaged, but they may nevertheless wish to engage with [SPaDE](docs/tlad001.md#spade) itself to influence the nature of that network.
If there are no better guidelines and suggestions available by then a first contribution might be to offer some.
